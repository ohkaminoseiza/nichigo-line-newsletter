# 設定手順（LINE週刊配信）

毎週土曜の朝、GitHub Actions が Anthropic API でオーストラリアの話題（4週で4テーマを循環）を作成し、
LINE公式アカウントからLINEグループへ送信します。

```
GitHub Actions（毎週土曜 7:45 起動）
  → Anthropic API（Web検索で事実確認しながら原稿を作成）
  → LINE Messaging API（グループへプッシュ送信）
  → 配信記録（newsletter/state.json と archive/）をリポジトリに保存
```

必要な値は3つだけです。**チャネルシークレットとチャネルIDは、この仕組みでは使いません。**

| GitHub Secrets の名前 | 中身 | 手に入れる場所 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Anthropic の APIキー | platform.claude.com の API Keys |
| `LINE_CHANNEL_ACCESS_TOKEN` | チャネルアクセストークン（長期） | 手順1 |
| `LINE_GROUP_ID` | 送信先グループのID（`C` で始まる） | 手順3 |

---

## 手順1　チャネルアクセストークン（長期）を発行する

1. [LINE Developers コンソール](https://developers.line.biz/console/) で、作成済みのチャネルを開く
2. 「Messaging API設定」タブの一番下、「チャネルアクセストークン（長期）」の「発行」を押す
3. 表示された長い文字列を控える（これが `LINE_CHANNEL_ACCESS_TOKEN`）

## 手順2　公式アカウントがグループに参加できるようにする

「Messaging API設定」タブで次を確認します（編集リンクから LINE Official Account Manager が開きます）。

- 「グループトーク・複数人トークへの参加を許可する」→ **有効**（初期設定は無効）
- 「応答メッセージ」→ **オフ**（グループで自動応答が出ないようにするため）
- 「あいさつメッセージ」→ お好みで（グループ参加時には使われません）

## 手順3　グループIDを調べる

グループIDはWebhookでしか分からないため、Google Apps Script で一時的な受け口を作ります。

1. [script.google.com](https://script.google.com/) で「新しいプロジェクト」を作る
2. `tools/line_group_id_webhook.gs` の中身をすべて貼り付け、
   `CHANNEL_ACCESS_TOKEN` の行に手順1のトークンを貼り付けて保存
3. 右上「デプロイ」→「新しいデプロイ」→ 歯車から「ウェブアプリ」を選択
   - 実行ユーザー：**自分**
   - アクセスできるユーザー：**全員**
   - 「デプロイ」を押し、アクセスを承認して、表示された **ウェブアプリのURL** をコピー
4. LINE Developers の「Messaging API設定」で
   - 「Webhook URL」に、コピーしたURLを貼り付けて「更新」
   - 「Webhookの利用」を **オン**
   - （「検証」ボタンでエラーが表示されることがありますが、Apps Script の仕様上よくあることで、実際には動きます）
5. LINEアプリで配信先のグループを開き、公式アカウントを招待する
   → 公式アカウントが「このグループのIDは C… です」と返信します
   （返信がない場合は、グループで「ID」と送信してみてください）
6. 表示された `C` で始まる文字列を控える（これが `LINE_GROUP_ID`）
7. 控えたら、「Webhookの利用」をオフにし、Apps Script のデプロイは削除してかまいません

## 手順4　GitHub に3つの値を登録する

リポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」で、
上の表の3つを登録します。

（使うモデルを変えたい場合は、同じ画面の「Variables」タブに `NEWSLETTER_MODEL` を作り、
モデル名を入れます。未設定なら `claude-sonnet-5-5` を使います）

## 手順5　試してみる

1. リポジトリの「Actions」タブ →「北海道日豪協会だより（LINE週刊配信）」→「Run workflow」
2. **mode を「preview」** のまま実行すると、送信せずに原稿だけ作ります。
   実行結果のページ（Summary）に原稿が表示されるので、内容を確認します
3. 問題なければ、**mode を「send」** にして実行すると、LINEグループへ送信され、配信記録が保存されます

以降は、毎週土曜 7:45 に自動で動きます。GitHub の定時実行は混雑時に数分〜十数分遅れることがあり、
原稿作成にも数分かかるため、届くのはおおむね8時前後です。

## 運用メモ

- **テーマや文体を変えたいとき**：`newsletter/prompt_spec.md` を編集してください。
  「### 第1週」〜「### 第4週」の見出しはプログラムが読み取るので、名前を変えないでください。
- **次にどの週を配信するか・配信済みの題材**：`newsletter/state.json` に記録されます。
  `next_week` を書き換えれば順番を変えられます。`history` にある題材は重複しないよう避けられます。
- **送った原稿の控え**：`archive/` に日付ごとに保存されます。
- **失敗したとき**：GitHub から失敗通知のメールが届きます。Actions の実行ログに理由が表示されます。
  原稿に不備があった場合は1回だけ自動で書き直しを依頼し、それでも必要な項目がそろわなければ送信しません。
- **LINEの無料通数**：グループへの送信は「グループの人数分」として数えられます。
  無料のコミュニケーションプランは月200通なので、月4〜5回配信なら、グループが40人程度までは無料枠に収まります。
  それを超える場合はライトプラン（月5,000通）などへの変更が必要です。
- **チャネルシークレット**：この仕組みでは使いません。リポジトリやコードには書かないでください。
